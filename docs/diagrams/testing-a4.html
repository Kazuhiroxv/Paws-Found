Why more than one kind of test
Finding 1 · endpoint testing

A router fault no unit could show

Every handler in api/ was correct on its own, but api/index.php passed only the first two path segments to most of them, so a third was silently dropped: GET /api/matches/1/claims answered with the match. Only asking the running API for endpoints it does not have could find it. Fixed; audit cases EH-07 to EH-10.

Finding 2 · measuring, not only scanning

Contrast that axe-core could not see

axe reported zero violations, but it cannot judge text over a photograph. Measuring the rendered pixels behind each line of text, at four screen widths, found three paragraphs under WCAG AA, the worst at 1.17:1, on pages axe had called clean. Fixed, then re-measured: every line now passes at every width.

Every fix is proven red first

A regression test is run against the old code before the fix, and must fail there. Examples from the final fixes: the edit freeze (EM-03, 04, 05, 05b, 13 failed before), and refusing a reset to the current password (RS-1a–g, RS-4a).
